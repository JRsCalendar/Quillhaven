# Quillhaven

羽笔港湾：安放故事与写作伙伴的地方。

## 启动与网页自动回复

需要 Node.js 22.13 或更新版本（当前使用 Node 26），以及已安装并登录 ChatGPT 账号的 Codex。首次安装运行 `npm ci`，之后双击 `启动 Quillhaven.cmd`，或在项目目录运行 `npm start`，打开 http://127.0.0.1:5173。

本机 Codex 已注册名为 `quillhaven` 的 STDIO MCP 服务。注册不会自动刷新正在进行的对话的工具列表；重启 Codex 后加载。连接脚本使用绝对路径，工作目录不影响数据位置。若移动项目，需要更新 MCP 配置。

现在的使用步骤：

1. 双击启动脚本，保持服务窗口运行。不需要每次先打开 Codex 桌面窗口，只要本机 Codex 已登录。
2. 等聊天顶部显示“Codex · 自动回复已就绪”。首次默认使用 Codex 存档，之后恢复上次的自动回复开关和身份。
3. 直接在网页发消息。后台会自动读取、思考并回复；明确要求编辑文档时，会调用 MCP 工具修改，页面自动同步。无需回到 Codex 发提醒。
4. 顶部“暂停”停止自动处理，“开启”恢复。点击伙伴存档里的“用这个存档自动回复”可以切换身份；当前一次只运行一个自动伙伴。
5. 结束时在服务窗口按 Ctrl+C：网页服务、它启动的 Codex 写作进程及 MCP 子进程会一起关闭。只关浏览器不会停止后台服务。

后台使用官方 Codex app-server，以现有 ChatGPT/Codex 登录启动独立的写作会话，使用你在 Codex 配置中的模型；顶部状态的提示可查看实际模型。它使用 Codex 额度，不需要 OpenAI API 密钥，不会自动切换成按量计费 API。

自动会话保留运行期间的上下文；重启后读取所选伙伴的记忆和最近聊天，也可通过工具查阅更早记录。它不会复制当前 Codex 开发对话的全部历史。新确认的设定与进度由伙伴主动保存为记忆，聊天正文始终独立落库。

消息按顺序处理，空闲时不调用模型。断线、额度不足或生成失败会暂停队列并显示错误，点击“重试”才重跑；如果之前已经修改过文档，请先核对。处理中点击暂停会中断本轮，已成功的文档修改不会自动撤销。进程意外退出后的未完成消息也会等待明确重试。

自动回复仅开放写作工具，不开放终端、浏览器、其他插件或外部通讯。未来仍可加入模型 API 适配器和远程连接，本版本尚未实现这些路径。

如果只想保留手动 MCP，点“暂停”即可。开发时也可设置 `QUILLHAVEN_AUTOREPLY=off` 启动无自动运行器的服务。`QUILLHAVEN_CODEX_BIN` 可指定 Codex 可执行文件的绝对路径；默认会自动查找本机安装。

手动联调时，开发者可运行 `npm run mcp:client`。这是使用官方 SDK 的真实 MCP 客户端，持续通过 STDIO 连接同一个服务；每行输入 `{"name":"workspace_overview","arguments":{}}` 形式的调用，`/tools` 列出工具与参数，`/quit` 断开。它本身不会生成答案。不要让手动客户端和自动运行器同时用同一身份处理同一批消息。

其他本机 MCP 客户端可参考 `mcp-config.example.json`，按客户端要求放入其配置。只支持本机 STDIO，不提供远程 HTTP MCP 入口。

## 文档、聊天和伙伴存档

- 文档树支持新建、子文档、折叠、搜索、行内改名及右键改名/删除。根目录名称默认“你的世界”，可编辑并同步面包屑。
- 文档详情从左侧滑出，使用圆润的气泡连接处；正文自动保存，显示更新时间、逻辑行号和字数。顶部按钮切换日夜模式。
- 中间聊天只显示香港时间的今天与昨天；右侧按日期收纳全部历史。每次分页读取 80 条，旧记录不会被自动删除。
- 支持指定伙伴/所有伙伴、Enter 发送、Shift+Enter 换行、多行草稿。消息状态区分等待读取、已读和已回复。旧版仅本地记录不自动投递。
- Agent 回复、文档修改会自动显示。Agent 先读取文档版本，精确替换指定文本；版本过期或匹配不唯一时拒绝修改，必须重读。
- 网页与 Agent 对不同字段的编辑会合并；同一内容冲突时保留原文和“本机冲突副本”，不会直接覆盖。旧版本写入数据库，可通过 MCP 的 `document_history` 读取并按用户要求恢复。
- 伙伴名字和记忆持久保存；灰色离线，蓝色表示 MCP 身份会话在线。断开时立即离线，异常退出最迟约 45 秒过期。可在伙伴存档内断开连接。
- 点击伙伴名字，在存档窗口底部选择“删除存档”，确认后删除该身份及记忆，并停止其自动回复、断开连接。文档和历史聊天保留；页面内无法撤销，旧页面同步也不会恢复已删除的身份。
- 记忆由用户或 Agent 主动保存，采用冲突校验；不会自动搬运当前 Codex 对话历史，也不会在浏览器关闭时神奇地产生摘要。

## 数据保存与迁移

正式文档、伙伴记忆、聊天、收件回执、旧版本都在项目 `data/quillhaven.sqlite` 中。网页服务和 MCP 服务共用数据库，使用事务与 WAL；浏览器关闭后数据仍保留。数据库不会由静态服务器对外提供，只监听 127.0.0.1。

第一次打开新版网页会迁移**该浏览器、该访问地址**里的旧 localStorage 文档和 IndexedDB 聊天。迁移按浏览器编号幂等执行，原始数据保留在数据库的迁移备份中；旧 IndexedDB 不删除，旧文档另存浏览器备份。不同浏览器的同名内容不会据此相互覆盖。请用原先的浏览器和地址打开一次，才能迁移那里的数据。

浏览器继续缓存文档和未同步修改；断网时编辑留在浏览器，下次启动会尝试合并。消息提交失败时输入保留，重试使用同一消息编号以避免重复。聊天草稿和主题偏好仍保存在浏览器。

顶部导出按钮导出文档、伙伴记忆与全部聊天的 JSON（不包含历史版本）。完整备份应在网页和 MCP 进程均停止后复制整个 `data/` 目录。备份导入界面尚未实现。删除文档前有确认；历史版本保留在数据库中。不要清空 `data/`，不要直接用 file:// 打开页面。

本版本适合个人本机使用，不提供网站账户登录、跨设备共享、远程暴露或 API 密钥管理。应用不读取或保存登录令牌，由 Codex 官方进程管理已有登录。

## MCP 工具

| 工具 | 用途 |
| --- | --- |
| workspace_overview | 查看文档树与可选伙伴 |
| connect_agent | 新建或恢复身份并读取记忆 |
| read_inbox | 读取尚待该伙伴回复的消息，并标记已读 |
| read_chat | 按日期和游标读取交流上下文 |
| reply_to_chat | 回复网页并关联已处理消息，支持幂等重试 |
| read_document | 读取正文、逻辑行和版本 |
| create_document | 按用户要求新建文档或子文档 |
| edit_document | 按版本精确替换正文，原子提交 |
| document_history | 查看最近 50 个旧版本 |
| save_memory | 保存身份记忆，检查是否被同时修改 |
| disconnect_agent | 断开本次身份连接 |

## 开发与验证

`npm run check` 检查所有源码语法，`npm test` 运行存储、日期、并发、迁移、HTTP 和真实 MCP STDIO 集成测试。测试数据写入系统临时目录并清理，不使用正式数据库。

`npm run doctor` 只检查 Codex 登录状态和模型列表，不输出令牌、不调用模型。`npm run test:live` 在隔离数据库中实际调用一次 Codex，验证真实模型能通过 MCP 编辑文档，会使用 Codex 额度。`scripts/preview-automatic.mjs` 是隔离 UI 验证入口（5175 端口），结束会清理临时数据。

- `dist/`：原生 HTML/CSS/JavaScript 页面，含旧浏览器数据读取和新后端同步。
- `lib/database.mjs`：SQLite 存储、迁移、冲突校验与共享业务逻辑。
- `server.mjs`：静态页面及同源本机 API，校验 Host、Origin 和写请求头。
- `lib/auto-reply.mjs`：自动队列、状态、暂停/重试和子进程生命周期。
- `lib/codex-rpc.mjs`、`lib/codex-writer.mjs`：官方 Codex app-server 协议、登录检查、写作会话和受限工具调用。
- `lib/mcp-connection.mjs`：自动运行器到文档工具的真实 MCP 连接。
- `dist/automatic.js`：网页自动回复状态和控制。
- `mcp-server.mjs`：官方 MCP SDK 的 STDIO 工具服务。
- `scripts/mcp-client.mjs`：真实 MCP 客户端，用于联调或工具尚未重载的会话。

MCP 实现参考 [官方 TypeScript SDK](https://ts.sdk.modelcontextprotocol.io/v2/)；自动回复使用 [Codex app-server 官方接口](https://learn.chatgpt.com/docs/app-server)。动态工具接口属于实验能力，Codex 更新后若接口变化需检查兼容性。界面沿用用户提供截图的简洁分栏与细分隔线，不依赖远程字体或图片。
